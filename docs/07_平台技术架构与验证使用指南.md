# BCU_3M9B 平台技术架构与验证使用指南

> 本文是统一开发仓库的操作与证据说明，面向接手后的开发、复测和论文数据审计。
> 它总结当前仓库中的 Python v2、Python v1 和 MATLAB 快照如何协作，但不替代
> [项目现状与边界](01_项目现状与边界.md)、[验证覆盖矩阵](03_验证覆盖矩阵.md)
> 或 [八路径总门禁记录](provenance/2026-09-02_八路径总门禁.md)。

## 1. 先看结论

当前统一仓库的职责边界是：

- `python_bcu_v2/` 是主开发平台。新增算法、失败测试、数值诊断和统一验证入口优先在这里完成。
- `python_bcu/` 是兼容基线。v2 通过兄弟目录复用其中的 `bcu_3m9b` 案例、网络、约简模型和基础数据结构；除非登记了明确缺陷并配套回归测试，否则不改 v1。
- `matlab_platform/` 是只读参考方程和原生验证平台。MATLAB 的结果必须同时通过网络残差、能量/物理约束和坐标一致性检查，不能因为 MATLAB 输出了一个数值就直接称为物理真值。
- MATPOWER 7.1、本地 `.mat` 参考、运行结果和缓存是外部依赖或可重生工件，不进入 Git。
- 阶段 7 的阻尼敏感性研究按用户要求跳过；`experiments/test_damping_study.py` 只验证研究驱动的门控接口，不是 24 个案例的研究证据。

当前八路径报告（`validation/reports/full_xval_latest.json`）登记为 8 条
`MATLAB_XVAL_FULL`。这里的 `FULL` 只表示该路径登记的指定输出已经按对应参考进行比较，
不表示穷尽所有周期数学根，也不表示稳定区域连续密度覆盖。当前 `spm_cct` 使用同坐标的
`spm_cct_v2.json`；历史 `spm_cct_v1.json` 的 `E_critical=3.3757`、`CCT=0.2053 s`
属于坐标混用审计，不能作为当前自足 SPM 的输入或验收目标。

## 2. 仓库结构和证据等级

```text
BCU_3M9B-development/
├── matlab_platform/       # MATLAB R2024a 快照；B3_MM 只读，verify/ 可增加诊断器
├── python_bcu/            # Python v1 兼容基线；v2 的兄弟目录依赖
├── python_bcu_v2/         # Python 3.12 主开发平台、测试和八路径入口
├── validation/
│   ├── references/        # 紧凑、带 schema 的参考 JSON；不存完整工作区
│   └── reports/           # 被忽略的运行产物、日志和诊断快照
├── experiments/           # 研究驱动和门控测试；阶段 7 尚未执行
├── scripts/               # 环境审计、依赖引导、统一回归、文档门禁
├── docs/                  # 权威文档、来源审计和阶段记录
└── SOURCE_MANIFEST.csv    # 来源文件、提交、哈希和导入时间
```

证据按照强度和含义分层：

1. **静态检查**：读代码、配置、接口和文件清单，只能证明代码表象。
2. **物理不变量**：Kron 约简、网络 P/Q 残差、COI 约束、正电压、能量项、type-1 分类等。
3. **Python 内部验证**：单元测试、固定种子审计、RK45/Radau 一致性和变异测试。
4. **MATLAB 原生证据**：在目标 MATLAB 版本实际运行的静态、CUEP、能量和轨迹导出。
5. **指定输出的跨平台对照**：两端坐标、单位、故障、步长和检查点一致后，逐变量比较。
6. **有限搜索证据**：有限初值、网格或同伦结果只能说明已覆盖的搜索范围，不能写成全根证明。

任何报告都应同时写出：验证对象、参考来源、比较范围、最大误差、容差、运行环境、
限制和状态。`checks_passed/checks_total` 是检查项计数，不是路径覆盖率。

## 3. 总体技术架构

### 3.1 数据流

```text
MATPOWER case / bcu_config
          │
          ├── MATLAB: setup_bcu_paths → Cal_MM_Static* → Cal_MM_CCT*/NumSim*/Region
          │             │                         └→ verify 导出紧凑参考/诊断
          │             └── B3_MM 原始方程、base workspace、MATPOWER Ybus
          │
          └── Python v2: config → v1 bcu_3m9b 构造 static
                         ├→ reduced CCT / numerical / region
                         ├→ SPM algebraic network + fault1 DAE + CUEP + energy
                         ├→ two-machine region 示例
                         └→ reference_io → run_full_xval 八路径报告
                                      ↑
                         validation/references/*.json（紧凑、可校验）
```

两端共享的比较契约包括：`case9_v2`、故障线路/位置、发电机顺序、COI 坐标、功率/电压/导纳
单位、故障和清除时间、积分步长、网络节点排序、参考版本和容差。绝对发电机角含有 COI
漂移时，必须比较 COI 相对角；不能把不同参考系的角度直接相减后宣布不一致。

### 3.2 模型分层

| 层 | Python v2 | MATLAB | 责任 |
|---|---|---|---|
| 案例和参数 | 复用 `python_bcu/bcu_3m9b`，由 v2 config 组装 | `bcu_config.m`、`case9_v2`、MATPOWER | 定义案例、基频、惯量、阻尼、机械功率、暂态电抗和内电势 |
| 网络 | `network.py`、`spm_energy.py` | `B3_MM` 中的 `Yred/Yfull_mod` 和 `Fun_AE*` | 形成预故障、故障后网络，并解代数状态 |
| 发电机 | v1 基础方程 + v2 CCT/DAE 封装 | `F_3M9B_*`、摆动方程脚本 | 计算角、速度、机械/电气功率和 COI |
| SPM | `spm_energy.py`、`spm_dae.py`、`spm_cuep.py`、`spm_region.py` | `Cal_MM_*_SPM.m`、`Fun_Cal_*_SPM.m` | 结构保持网络、MGP/CUEP、五项势能和轨迹 |
| 交叉验证 | `reference_io.py`、`run_matlab_xval.py`、`run_full_xval.py` | `verify/` 导出器和诊断器 | 用紧凑参考逐对象比较，不把参考文件当作算法输入 |

## 4. Python v2 技术架构与技术路径

### 4.1 基础和约简路径

v2 不复制一份 v1 案例实现，而是把统一仓库中的 `python_bcu/` 加到导入路径，调用
`bcu_3m9b.build_static_result()` 等基础构造器得到 `static`。这样可以在 v2 中增加
验证、SPM 和报告，而不改变 v1 的兼容行为。

约简模型的基本链路是：

```text
case9_v2 + 参数
  → Ybus / Kron 约简 Yred
  → 预故障 SEP
  → 故障网络轨迹或能量逃逸
  → type-1 UEP/CUEP 搜索
  → 势能差与 LEA CCT
  → 数值 REA 或区域抽样
```

需要分别检查 `reduced_cct`、`reduced_numerical` 和 `reduced_region` 的对象，不能用
约简 CCT 的成功替代数值轨迹或稳定边界的验证。

### 4.2 SPM 能量路径

`bcu_v2/spm_energy.py` 实现以下底层能力：

- 用全网络复数导纳和内电势构造 SPM 网络 P/Q 代数残差；
- 给定发电机角时，以连续 warm-start 解网络角和负荷母线电压；
- 计算发电机电气功率；
- 计算 MATLAB 同源的五项势能 `Ep1`–`Ep5`；
- 在给定 `E_critical` 时计算能量法 LEA CCT。

`bcu_v2/spm_cuep.py` 在此之上增加严格 fault1 逃逸种子、MGP/候选分支、联合发电机—网络
平衡、type-1 分类、能量门禁和无外部临界能量依赖的自足 CCT。有效结果必须同时满足：

```text
网络残差 < 1e-8
联合平衡残差 < 1e-8
网络电压为正且有限
CUEP != SEP
type-1 分类成立
E_critical < 故障轨迹能量峰值
```

失败返回结构化状态（例如 `ENERGY_GATE_EXCEEDED`），不能用零值、旧 MATLAB 标量或默认
初值伪造 CUEP/CCT。

### 4.3 SPM 数值轨迹

`bcu_v2/spm_dae.py` 把 SPM index-1 DAE 视为约束流形上的降阶 ODE：发电机角和角速度
由 `scipy.integrate.solve_ivp` 积分；每次 RHS 评价用上一步网络状态 warm-start `root`，
解出网络角和电压，使 P/Q 代数残差保持很小。轨迹返回结构包含：

```text
time, delta_gen, omega_gen, theta_net, voltage_net,
algebraic_residual, phase_labels, converged
```

固定阶段是 `prefault`、`fault-on`、`clearing`、`postfault recovery`。比较时至少取
`t=0`、清除前、清除时、清除后 10/50/100 ms 和最终时刻；每个点逐变量报告角、速度、
网络角、电压、代数残差、能量和稳定性标志。单个末端点不能冒充完整轨迹验证。

### 4.4 SPM 稳定域和两机示例

`spm_region.py` 从 SEP 网络状态沿角度候选分段 warm-start 求解网络分支，返回平衡点角度、
网络角、电压、类型、残差、`branch_id` 和连续性误差。稳定流形按登记检查点比较；
有限点集不等于连续区域的无限密度覆盖。

`two_machine_region_3d` 和 `two_machine_region_3d_gfl` 是独立的两机三维示例，不能把其
平衡点证据反推为三机九节点 SPM 的证据。

### 4.5 紧凑参考读取

`bcu_v2/reference_io.py` 支持：

- 新 JSON：顶层 `schema_version`、`metadata`、`arrays`；复数用 `{"real": ..., "imag": ...}`；
- 旧 `.mat`：只作过渡诊断，不作为新报告的紧凑基准；
- schema、数组形状、复数实虚部和必需元数据校验；
- 错误或不可比较参考直接抛出/返回失败，不静默降级为零值。

当前 SPM CCT 的活动参考是 `validation/references/spm_cct_v2.json`；
`spm_cct_v1.json` 专门保留用于复现混合坐标问题。

## 5. MATLAB 技术架构与技术路径

### 5.1 入口和配置

`matlab_platform/run_bcu.m` 是配置驱动入口：定位项目根、调用 `setup_bcu_paths`、清除
运行时覆盖、读取 `bcu_config()`、校验配置、打印摘要、保存被忽略的参数快照，再按
`cfg.mode` 路由到八条路径。模式包括：

```text
reduced_cct, reduced_numerical, reduced_region,
spm_cct, spm_numerical, spm_region,
two_machine_region_3d, two_machine_region_3d_gfl
```

单次运行的参数真相是 `bcu_config.m` 中的 `cfg.xxx = ...`。`bcu_override(struct(...))`
是供 `run_bcu_sweep.m` 批量扫参的 persistent 覆盖通道；`run_bcu.m` 开头会执行
`bcu_override('clear')`，所以在单次入口前设置 override 不会保留。修改参数后应重新运行
`run_bcu.m`，不应把旧 base workspace 变量当成新配置。

### 5.2 MATLAB SPM CCT 调用链

```text
Cal_MM_Static_SPM.m
  → SEP / Yfull_mod / fault network
  → Fun_Cal_Exitpoint_SPM.m（故障 DAE 逃逸点）
  → Fun_Cal_MGP_SPM.m（MGP 轨迹迭代）
  → fsolve(@Fun_SEPfslove_SPM, x_init)（联合平衡）
  → Fun_Cal_PotentialEnergy_SPM.m（Ep1–Ep5）
  → LEA CCT / 与 REA 比较
```

`F_3M9B_SP_DAE.m` 和 `F_3M9B_SP_ODE.m` 描述结构保持模型的微分/代数动力学。
MATLAB 脚本大量使用 `evalin('base',...)` 和 `clear`，所以依赖调用顺序；直接运行依赖
`preset`、`postfault`、`Basevalue` 或 `Results_fsolve` 的脚本，可能得到变量缺失而不是
算法失败。`NumSim_MM_Gridframe_SPM.m` 必须在 SPM CCT 初始化和清除状态完成后运行。

### 5.3 MATLAB 与 MATPOWER 边界

MATPOWER 7.1 只作为本地依赖放在被忽略目录；`setup_bcu_paths` 需要其目录结构存在，
但本仓库不修改或提交官方 MATPOWER 源码。完整 `.mat` 工作区、轨迹和图像是运行产物，
需要时通过 `verify/` 导出紧凑 JSON，避免把数百 MB 工作区当作版本控制接口。

## 6. 已确认的 MATLAB 坐标问题与尚待确认疑点

### 6.1 已确认：`deltacoi` 未限定来源导致 CUEP 网络角混用

问题位置：`matlab_platform/B3_MM/Cal_MM_CCT_SPM.m`，当前快照约第 97 行：

```matlab
postfault.deltacoi=delta_tmp'*preset.m/sum(preset.m);
postfault.CUEP_delta=delta_tmp-postfault.deltacoi;
postfault.CUEP_net_theta=Results_fsolve((ngen+1):nbus)-deltacoi;
```

前一行刚把正确的 COI 平移写入 `postfault.deltacoi`，但后一行使用了未限定的
`deltacoi`，MATLAB 会从当前/base workspace 解析同名变量。审计记录的分支执行证据为：

- `postfault.deltacoi ≈ -1.997835`；base workspace `deltacoi ≈ -0.295690`；
- 写入的 projected 网络角与用实际 `postfault.deltacoi` 修正的 raw fsolve 网络角相差约 `4.16939`；
- 历史 `spm_cct_v1.json` 的 projected 网络状态代回正确 SPM P/Q 方程，网络残差约 `11.3454`；
  MATLAB 的 `Fun_SEPfslove_SPM` 残差范数约 `15.9068`，数值差异来自残差归一化，但两者都拒绝该状态；
- 直接使用 `Results_fsolve` 的 raw 网络角，再减去实际 `postfault.deltacoi`，网络残差约
  `4.2e-15~5.1e-15`，说明联合根本身可满足物理网络方程；
- 因此历史 `E_critical=3.3756797087` 是混合坐标状态的能量，不能直接当作当前物理 CUEP 的临界能量。

这不是“MATLAB 所有算法都错”的结论，而是一个可定位、可复现的状态投影错误：
`Results_fsolve` 的联合根、正确 COI 投影和错误存储字段必须分开审计。当前统一参考采用
同坐标的另一个正电压 type-1 候选：Python 与 MATLAB R2024a 均得到
`E_critical≈1.4927509038`、网络/联合残差约 `5.1e-15`、同窗故障能量峰值约
`5.5678499612`，LEA CCT 为 `0.149 s`。本仓库没有改写 `B3_MM`，而是通过只读诊断器隔离该问题。

推荐复现顺序：

1. 在 MATLAB 中运行 `Cal_MM_CCT_SPM.m`，保留当前会话的 base workspace。
2. 运行 `matlab_platform/verify/diagnose_spm_mgp.m`，记录 `postfault`、`Results_fsolve`、
   base `deltacoi` 和 physical-cuep 快照。
3. 运行 `matlab_platform/verify/probe_spm_candidate.m`，从独立候选重新 `fsolve`，再用
   同坐标网络残差和五项势能复核。
4. 用 `python_bcu_v2/run_full_xval.py` 检查报告是否引用 `spm_cct_v2.json`，而不是把
   `spm_cct_v1.json` 当作活动目标。

### 6.2 尚待确认：`voltage_MGP = theta_iter(no_MGP,:)`

`matlab_platform/B3_MM/Fun_Cal_MGP_SPM.m` 约第 65 行存在：

```matlab
voltage_MGP= theta_iter(no_MGP,:);
```

从变量名和后续 `voltage_iter` 的含义看，这是疑似复制错误；但只读诊断显示成功运行曾
进入“重复状态”退出分支，且成功返回的电压向量与角度向量不同，尚没有证据证明该行在
影响最终结果的分支中执行。因此文档和测试只能把它标成“疑似、待分支执行证据”，不能
写成已确认 MATLAB 缺陷，也不能借此解释 `3.3757` 与 `7.5767` 的历史差异。

## 7. 为核验 Python/MATLAB 一致性所做的测试

### 7.1 公式和物理不变量

两平台并行检查：

- `Yred = Ynn - Ynr * (Yrr \\ Yrn)` 的 Kron 约简结构和维度；
- 网络 P/Q 代数残差，且 SPM 网络使用内电势 `Epu`、网络电压不是网络角；
- COI 加权角和速度约束、发电机顺序、故障线路移除；
- 电压有限且为正、CUEP 与 SEP 不重合、type-1 分类；
- 五项势能和 CCT 交点；
- `LEA <= REA` 作为能量法保守性检查（仅在对应路径定义下使用）。

### 7.2 Python 内部测试

v2 单元测试确保接口、残差、阶段标签、网络分支和失败状态先于跨平台比较成立。
变异测试故意注入错误，确认测试确实能发现错误，而不是只检查“程序能运行”。

### 7.3 MATLAB 原生导出和诊断

`matlab_platform/verify/` 的导出器把 MATLAB 结果压缩为 JSON：只保留 Python 实际需要的
Yred/Yfull、SEP/CUEP、能量、CCT、区域点集和固定轨迹检查点，并记录 MATLAB 版本、来源
提交、case、fault、坐标和步长。`diagnose_spm_mgp.m`、`probe_spm_candidate.m` 和
`export_spm_energy_series.m` 是问题定位工具，不修改 `B3_MM`。

`t=0`、清除前、清除时、清除后 10/50/100 ms 和最终时刻。

### 7.5 变异测试

`python_bcu_v2/test_mutations.py` 已实际通过 9/9，覆盖：Kron 符号、摆动方程加速度符号、
故障线路移除、COI 权重、发电机顺序、能量角差符号、SPM P/Q 符号、网络电压/角度混用和
关闭分支连续性检查。该结果证明受控错误能被捕获，不单独提升任何路径的物理状态。

## 11. 统一回归入口和日志

完整回归由 `scripts/run_all_validation.ps1` 驱动。它按明确工作目录和 `-B` 依次运行 v1
smoke、v2 基础测试、SPM DAE/轨迹/CUEP/区域、联合审计、同伦、八路径报告、变异门禁、

```text
command
working_directory
start_time
end_time
exit_code
status
stdout_path
stderr_path
```

调用示例：

```powershell
& (Join-Path $repo 'scripts/run_all_validation.ps1') `
  -RepoRoot $repo `
  -PythonExe $py `
  -TimeoutMinutes 30
```

解释结果时注意：

- `PASSED`：该脚本在本轮退出码为 0；还需阅读其输出和适用范围；
- `FAILED`：测试或算法明确失败，应保留 stdout/stderr；
- `BLOCKED`：环境、依赖、超时或参考不可用，不能以历史数字替代；
- `NOT_COMPARABLE`：双方坐标、节点、单位、数组形状或方程不一致，先修比较契约；
- `APPROXIMATE/UNVERIFIED`：有可运行实现但证据尚不足，不能用于正式论文定量结论。

## 12. 常见问题和处理边界

| 现象 | 首先检查 | 正确处理 |
|---|---|---|
| `ModuleNotFoundError` | 当前 cwd 是否为 `python_bcu_v2`，v1 兄弟目录是否存在 | 按上面的 `Push-Location` 运行，不复制/重命名包 |
| `python` 或 `py` 找不到 | `$py` 的绝对路径和 `--version` | 使用实际 Python 3.12 路径；不能把旧日志当本轮通过 |
| MATLAB 变量不存在 | 是否按 `Static → CCT → NumSim/verify` 顺序运行 | 回到 `run_bcu.m` 或先完成初始化，不手动造零变量 |
| SPM 网络电压为零/负 | 初值、网络分支、残差和 warm-start | 返回结构化失败，不能保留零值 CUEP |
| `spm_cct_v1` 残差很大 | 是否把 projected 混合坐标当活动参考 | 使用 `spm_cct_v2.json`；v1 只用于坐标审计 |
| `run_full_xval.py` 很慢 | 先运行单项测试和 reference/schema 门禁 | 不把超时算通过，不自动重试崩溃实验 |
| MATLAB 与 Python 角度不一致 | COI 坐标、网络排序、单位和电压/角度列 | 先统一数据契约，再比较逐变量误差 |
| 想启动阻尼 24 案例 | 八路径总门禁是否已完成 | 当前阶段 7 明确跳过；未经新授权和闭环证据不得生成研究结论 |
