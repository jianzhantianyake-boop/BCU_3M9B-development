本轮执行记录（2026-09-01）：MATLAB R2024a 从本仓库工作目录成功启动并运行
`Cal_MM_CCT_SPM.m`，导出 `spm_cct_v1.json`；观测到 MGP、CUEP 和
`CCT(LEA)=0.2053 s`。Python 3.12 也已启动并完成参考 schema、SPM 原型和变异测试。
这些运行证明了环境与导出链可用，但不改变 `spm_cct` 的权威状态：Python 自足求解仍因
当前分支得到的 `E_critical=7.57668` 超过本次 Python 计算的故障能量峰值 `6.46886`
而未通过物理门禁。紧凑参考同时记录了 MATLAB raw fsolve 网络角与 projected 网络角，
两者最大坐标差约 `1.70`；因此 MATLAB 的 `E_critical=3.3757` 只能作为历史混合坐标
参考，不能替代物理一致坐标结果。统一报告 `validation/reports/full_xval_latest.json` 当前为
`5 MATLAB_XVAL_FULL + 1 UNVERIFIED + 1 APPROXIMATE + 1 UNVERIFIED`；其中五条
FULL 的误差和覆盖范围仍来自历史交叉验证证据，本轮只重新生成并校验了紧凑参考。

阶段 5 收尾记录：MATLAB 已导出固定轨迹检查点（`t=0、0.1、0.2、0.2053、0.21、
0.25、0.3 s`），Python 端已增加端点包含和检查点选择器，短时 RK45/Radau 一致性测试
通过。但在同一故障工况上进行 `0.3 s` 的长时 Radau 轨迹时，网络代数校正进入非有限
电压并触发 `array must not contain infs or NaNs`；这说明当前降阶 ODE 包装尚未保持
MATLAB 的 DAE 分支，`spm_numerical` 继续保持 `APPROXIMATE/UNVERIFIED`。下一轮应先
增加非物理解拒绝、结构化失败时间和隐式步级 Newton/分支连续性诊断，再谈检查点交叉验证。
